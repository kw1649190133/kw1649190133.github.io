无人机新规分析

前言

无人机行业关于规范管理方面，又多了两项新国标，GB 46750-2025和GB 46761-2025，都是2025年就已经发布的，不过2026年才实施。

协议对照

GB 46750-2025(无人机广播) GB 46761-2025 (UOM对接)
全称 民用无人驾驶航空器系统运行识别规范 民用无人驾驶航空器实名登记和激活要求
管什么 飞行中”我是谁、在哪、飞多快” 起飞前”有没有登记、有没有激活”
通信对象 广播给附近所有人 + 网络报送监管平台 HTTPS 直接跟 UOM 平台对话
通信协议 蓝牙/WiFi 广播 + 4G/5G/卫星网络 RESTful API (POST JSON)
加密方式 无加密（公开广播） SM4/CBC 加密（国密算法）
触发时机 靠自身动力移动全过程持续发送 实名登记/激活/注销时按次请求
发送间隔 ≤1秒 相同参数 ≤1分钟/次
是否可以关闭 不可以，一旦起飞必须持续发 按需调用
核心数据 21个运行参数（位置、速度、高度、状态…） 3个接口（验证实名、上报激活、注销）

与现有飞控、地面站的关联

举例对比

场景1：一架新出厂的四轴飞行器第一次飞

  • GB 46761 的流程（起飞前）:
    工厂 → UOM: 上报激活状态 = “激活”
    App → UOM: 验证实名状态 → 返回”正常”
    App 检查激活+实名都OK → 允许电机解锁

  • GB 46750 的流程（飞行中）:
    无人机 → 蓝牙广播: [0xFF,0xED,0xFE] 001=SNX123 008=22.5,113.9…
    无人机 → 4G网络上报: 同样数据发到监管平台
    地面接收系统: 解析”这台飞机在22.5°N,113.9°E, 高120m, 速度15m/s”

    场景2：飞机转让给新主人

  • GB 46761:
    旧主人App → UOM: 注销登记(TYPE=3所有权变更, token=xxx)
    新主人App → UOM: 验证实名 → 正常
    新主人App → UOM: 上报激活 = “激活”

  • GB 46750:
    （全程不受影响，飞机飞起来该广播什么还是广播什么）

飞行器的报文程序逻辑

  • 报文程序：
    前置设置，配置WIFI、蓝牙、4G，还有推送的地址等、
    程序启动，检测WiFi、蓝牙、4G是否可用。
    开始从飞控获取数据，获取遥控器位置，生成报文，检测报文内容是否正常，内录到机身内。
    开始广播，广播正常后，允许飞控起飞。
  • 监听程序：
    期间如果全部广播挂了，或者报文程序挂了，得给飞控指令悬停和返航。
    4G模块的断联不影响飞机的正常飞行，只需要将广播内容搜集起来，等连上之后再一块发。

考虑到实际情况，感觉报文程序记录的信息还是有点少，像飞机本身其实也应该具备一个“黑匣子”，启动后就开始记录飞机的全部状态，包括报文里不需要的电池电量等信息。如果是已经有黑匣子的飞机，那报文程序就可以直接从黑匣子读数据。

总结

GB 46761 管”能不能飞”（实名+激活门禁），GB 46750 管”飞的时候报什么”（持续运行识别广播）。两者互不替代、缺一不可，且 GB 46761 的激活状态应该是 GB 46750 报文里 运行状态(015) 字段的前置条件之一。
